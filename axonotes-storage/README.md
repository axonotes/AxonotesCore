# Axonotes Storage Service

**Secure blob storage API with streaming uploads, quota management, and S3-compatible backend.**

---

## About

The Axonotes Storage Service is a RESTful API built with Rust and Axum that handles encrypted blob storage for the Axonotes application. It manages file uploads/downloads, enforces per-user storage quotas, and integrates with S3-compatible storage backends (MinIO or AWS S3).

## Features

- **Streaming Uploads:** Efficient multipart uploads with incremental BLAKE3 hashing
- **Ed25519 Signature Verification:** Cryptographic proof of upload authorization
- **JWT Authentication:** Supports multiple OAuth issuers with JWKS validation
- **Dynamic Quota System:** Rhai-scripted rules evaluate JWT claims for flexible quota assignment
- **Rate Limiting:** Per-user rate limits for uploads, downloads, and quota checks
- **Local Caching:** SQLite metadata storage with automatic orphan cleanup

## API Endpoints

### Protected Routes (JWT Required)

| Method   | Path                         | Description                       |
| -------- | ---------------------------- | --------------------------------- |
| `POST`   | `/blobs`                     | Upload encrypted blob (streaming) |
| `DELETE` | `/blobs/{hash}`              | Delete blob (owner only)          |
| `GET`    | `/quota`                     | Get user quota information        |
| `POST`   | `/documents`                 | Create document record            |
| `DELETE` | `/documents/{id}`            | Delete document and blobs         |
| `PUT`    | `/documents/{id}/public-key` | Update document signing key       |

### Public Routes

| Method | Path                     | Description                  |
| ------ | ------------------------ | ---------------------------- |
| `GET`  | `/blobs/{hash}`          | Download blob by BLAKE3 hash |
| `GET`  | `/swagger-ui`            | API documentation            |
| `GET`  | `/api-docs/openapi.json` | OpenAPI specification        |

## Upload Flow

1. Client creates signature: `sign(hash || document_id || timestamp)`
2. Client streams blob to `POST /blobs` with query params
3. Service validates JWT, signature timestamp, and quota
4. Blob streamed to S3 with incremental BLAKE3 hashing
5. Signature verified using document's Ed25519 public key
6. Blob finalized, ownership recorded, quota updated

## Configuration

```toml
[jwt]
issuers = ["https://api.workos.com/..."]
dev_mode = false
signature_max_age_secs = 300

[storage]
endpoint = "http://minio:9000"
bucket = "axonotes-blobs"
access_key = "minioadmin"
secret_key = "minioadmin"
region = "us-east-1"
max_blob_size_mb = 100

[database]
path = "/data/metadata.db"

[rate_limits]
upload_per_minute = 10
download_per_minute = 100
quota_per_minute = 60

[[quota_rules.rule]]
name = "enterprise_users"
condition = 'jwt.contains("org_id") && jwt.plan == "enterprise"'
quota_gb = 500

[quota_rules.default]
quota_gb = 1
```

## Quota Rules

Quotas are evaluated using [Rhai](https://rhai.rs/) scripts against JWT claims:

| Rule       | Condition                                            | Quota  |
| ---------- | ---------------------------------------------------- | ------ |
| Enterprise | `jwt.contains("org_id") && jwt.plan == "enterprise"` | 500 GB |
| Pro        | `jwt.plan == "pro"`                                  | 50 GB  |
| Beta       | `jwt.beta == true`                                   | 10 GB  |
| Free       | `jwt.plan == "free"`                                 | 2 GB   |
| Default    | (fallback)                                           | 1 GB   |

Rules are hot-reloadable - the config file is watched for changes.

## Database Schema

| Table            | Purpose                                    |
| ---------------- | ------------------------------------------ |
| `users`          | Track storage usage per user               |
| `documents`      | Document metadata with Ed25519 public keys |
| `blob_ownership` | Links blobs to users and documents         |

## Tech Stack

- **Framework:** [Axum](https://github.com/tokio-rs/axum)
- **Storage:** AWS SDK S3 (MinIO compatible)
- **Database:** SQLite with WAL mode
- **Authentication:** JWT with JWKS validation
- **Cryptography:** Ed25519 (dalek), BLAKE3
- **Scripting:** Rhai for quota rules
- **Documentation:** Utoipa/Swagger
